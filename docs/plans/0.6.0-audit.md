# 0.6.0 — The audit pass

**Contract 1.1.0** (no change) · Status: planned

## Goal

One scheduled pass that checks the memory against every fixed point available,
and emits a reviewable diff. Not reflection — verification.

## Why now

`IDEAS.md` §5 took apart the "meditation" idea and found that five of its six
steps have oracles and one does not. This release builds the five and refuses
the sixth. It also gives Anthropic's `/dream` something to run *against*:
dreaming proposes a consolidation using model judgement; `amk audit` says whether
that consolidation broke anything.

## Contract impact

None. Every check reads existing fields.

## Design

```
amk audit
  ├─ contract     loader over every scope                    → errors, warnings
  ├─ graph        orphans, cycles ≥3, unreachable clusters   → structural gaps
  ├─ drift        numeric claims vs. atoms                   → drift gaps
  ├─ eval         cases + baseline comparison                → eval gaps
  ├─ expiry       validUntil vs. now              (0.3.0)    → expiry gaps
  ├─ escalation   rate, uncovered queries          (0.5.0)   → coverage findings
  └─ duplicates   near-identical atoms                       → merge candidates
        │
        ▼
   one diff + one gap set, reviewable, nothing applied
```

Six of the seven exist. This release adds **duplicates**, wires the rest into a
single pass, and defines the output format.

### Near-duplicate detection, without a model

Token-set Jaccard over the existing token cache, on `title + summary + keywords`.
Above a threshold (default 0.8), two atoms are flagged as merge candidates.

This is cheap, deterministic, and explainable — three properties an embedding
comparison does not have here. It will miss paraphrases that share no vocabulary,
and that is an accepted limitation, stated in the docs rather than papered over.

**It never merges.** Deciding which of two overlapping atoms survives is a
judgement about meaning; the pass flags the pair as a gap of kind `duplicate` and
stops. A human or a proposing agent merges. Auto-merge would silently destroy
knowledge, which is the one thing this project exists to prevent.

Cost is O(n²) on token sets. At 500 atoms that is 125k set comparisons —
milliseconds. Above ~2000 atoms it needs blocking by category; do not build that
until someone has 2000 atoms.

### The output

Two artifacts, both reviewable:

- **`audit.md`** — grouped by severity, each finding with the check that produced
  it, the atoms involved, and the suggested action. Written for a human.
- **the ledger** — findings that are genuinely gaps get observed, so recurrence
  counting applies and a finding that keeps coming back sorts up.

Not everything becomes a gap. A warning that fires on every run is noise in a
ledger. Rule: **a finding becomes a gap when it names missing or wrong
knowledge**; it stays a report line when it names structure.

### Composing with `/dream`

Anthropic's consolidation runs on plain memory files and emits a reviewable diff
(see [`LINKMAP.md`](../../LINKMAP.md) §4 — press-sourced, unverified). The
composition:

```
/dream proposes a consolidation  →  amk audit --against <diff>  →  verdict
```

`--against` loads the proposed state instead of the current one and reports what
changed in *verifiable* terms: does it still satisfy the contract, does the eval
still pass, did any atom become unreachable, was anything with an open gap
pruned. Dreaming brings judgement; audit brings the fixed points.

This is the concrete form of the positioning in `IDEAS.md` §3, and it is worth
building even if `/dream` changes shape, because "verify a proposed memory state
before adopting it" is useful against any proposer — including an agent's own
bulk edit.

### What is refused

No check asks the model whether its reasoning was sound. `IDEAS.md` §5 explains
why: an agent auditing itself with the model that produced the memory has no
independent signal. The pass is named `audit`, not `reflect`, and the docs say
this in the first paragraph so nobody adds it later by accident.

## Surfaces

**CLI**

```bash
amk audit                      # everything, all scopes, writes audit.md
amk audit --scope research     # one scope
amk audit --only expiry,drift  # one or more checks
amk audit --against <path>     # verify a proposed state
amk audit --fix                # apply only mechanically safe fixes
```

`--fix` covers exactly: regenerating `_index.md`, removing a `linkLabel` with no
`link`, and quoting an unquoted date. Nothing that requires judgement. The list
is short on purpose and every addition to it needs an argument.

`amk doctor` becomes an alias for `amk audit --only contract,eval,drift` — the
fast subset — with a line pointing at the full pass.

**MCP** — `memory_audit`, returning structured findings. An agent about to do
bulk edits can run it before and after, and see what it broke.

## UX / DX / AX

**User (UX).** `audit.md` is the artifact. It must be readable by someone who
has not thought about this system for three weeks, which means: most severe
first, every finding says *what to do*, and it opens with one line of summary.
A wall of undifferentiated warnings is how audit output gets ignored, and audit
output that gets ignored is worse than none.

Second rule: **a clean audit must say so and be short.** "7 checks, nothing to
fix" is a good day and should look like one.

**Developer (DX).** One command in CI. Exit code 0 when clean, 1 on findings
above a configured severity — so it can gate a merge without arguing about
warnings.

Each check must be independently runnable and independently testable. That is
also why `--only` exists: debugging a single detector should never require
running the eval suite.

**Agent (AX).** `memory_audit` gives an agent a way to check its own work
against something that is not itself. That is the honest version of the
self-observation idea and worth naming as such in the tool description.

The findings must be *actionable by an agent*: each carries the atom ids, the
check name, and — where one exists — the exact command or write that would
resolve it.

## Tests

- [ ] each of the seven checks runs standalone and reports correctly
- [ ] `--only` runs exactly the named checks
- [ ] near-duplicates: identical atoms flagged, unrelated atoms not, threshold
      configurable, deterministic ordering
- [ ] duplicates are **never** auto-merged, even with `--fix`
- [ ] `--fix` applies only the three safe fixes and leaves everything else
- [ ] `--against` detects: a pruned atom with an open gap, an atom made
      unreachable, an eval regression, a contract violation
- [ ] a clean memory produces a short report and exit 0
- [ ] structural findings do not enter the ledger; knowledge findings do
- [ ] the audit is idempotent: two consecutive runs produce identical output
- [ ] `amk doctor` and `amk audit` never disagree on a shared check (the same
      class of bug already found once — see `SOURCEMAP.md` §1.3)

## Risks

**Audit fatigue.** Seven checks on a real memory will produce a lot on the first
run. Mitigation: severity ordering, a `--baseline` that accepts current findings
so only new ones surface, and a clean report that is genuinely short.

**`--fix` grows.** Every safe fix invites "and this one too". Mitigation: the
three are listed in the docs and adding a fourth requires an argument in the
plan file. Judgement-requiring fixes belong to `--against`, where a human sees
the diff.

**Duplicate false positives.** Two atoms that legitimately share vocabulary —
`pricing.plans` and `pricing.plans-enterprise` — will flag. Mitigation: the
threshold is configurable, and a flagged pair can be marked `x-duplicate-ok` as
an extension field, which the check honours. Extension fields exist for exactly
this.

## Done when

- [ ] `amk audit` on the example produces a report worth reading
- [ ] `--against` catches a deliberately harmful proposed state in a test
- [ ] `docs/AUDIT.md` states the refusal of introspection in its opening

## Kill criteria

- If findings are mostly ignored in practice, the problem is the report, not the
  checks — fix the report once, and if it is still ignored, cut the pass to the
  three checks people actually act on.
- If `--against` is never used because nothing proposes bulk states, drop it and
  keep the checks.
