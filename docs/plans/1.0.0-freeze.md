# 1.0.0 — Freeze and conformance

**Contract 1.1.0, frozen** · Status: planned

## Goal

Stop adding to the contract and make it something a stranger can implement
correctly in another language, verified rather than promised.

## Why now

`VERDICT.md` ends on a claim this release has to make true:

> The code is the perishable part. `CONCEPT.md` and `CONTRACT.md` are the
> durable ones.

A contract nobody has reimplemented is a hypothesis. `CONTRACT.md` §7 already
defines conformance levels L1–L4 and asserts L1 is a weekend of work in any
language — asserted, never tested. Until someone can *check* their
implementation, the levels are decoration.

Freezing is also the honest response to four releases of contract pressure. If
1.1.0 has survived durability, scopes, escalation and audit without a breaking
change, it has earned the freeze. If it has not, that is the finding and 1.0.0
waits.

## Contract impact

**Freeze at 1.1.0.** After this release:

- no new core fields, ever, in 1.x
- new standard fields only with a plan file arguing the §4.3 bar (name the
  consumer that breaks without it)
- extension fields remain unrestricted and free — that is where growth goes
- `x-*` and `_*` stay reserved for users in perpetuity

## Design

### The conformance suite

A language-neutral fixture set plus expected results, so an implementation in
Python, Go or Rust can prove its level.

```
conformance/
  cases/
    L1/  parse-*.md, core-*.md, extension-*.md
    L2/  duplicate-*/, dangling-*/, cycle-*/
    L3/  roundtrip-*.md
    L4/  ledger-*.jsonl
  expected/
    L1.json   { case: "core-missing-lang", diagnostics: ["E_CORE_MISSING"] }
    ...
  RUNNER.md   what a runner must do, in prose, in ~2 pages
```

Expected results are **diagnostic codes, never messages**. Messages are prose and
may be reworded in a patch; codes are API. This is contract R10.2 applied to the
suite itself.

Our own implementation runs it in CI as `npm run conformance`, which means the
suite cannot rot — if it drifts from the code, our own build fails first.

**The close decision:** ship a runner, or specify one? Shipping a JS runner
helps nobody writing Go. Specifying it in two pages of prose, with a JSON
expectations format any language can read, is what makes L1-in-a-weekend
plausible. Specify, and provide ours as one reference implementation among
hopefully several.

### The fixtures earn their keep by being nasty

Every fixture exists because it broke something, in this repo or in the source
it came from. The ones already known:

- reciprocal edges A↔B — must load clean, must not be reported as a cycle
- `priority: 10` — must survive the round trip
- `keywords: ["1500"]` — must stay a string
- a value containing both quote kinds — must become a block scalar
- a fenced code block inside a bundle — must not parse as an atom
- a `linkLabel` with no `link` — warns, does not fail
- a `.markdown` destination — does not round-trip through `pathForId`
- umlauts in titles, ids, and keywords

That list is the accumulated bug history from `SOURCEMAP.md` §1.3 and this
project's own test suite, turned into something portable. It is the most valuable
part of this release.

### Documentation freeze

`CONCEPT.md` and `CONTRACT.md` get an explicit stability statement and a
canonical URL. Everything else stays free to change.

## Surfaces

```bash
amk conformance                    # run the suite against this implementation
amk conformance --level L2         # stop at a level
amk conformance --report           # emit a badge-able summary
```

MCP: `server/discover` `instructions` and `memory_contract` both report the
implemented level. They already do — this release makes it verified rather than
declared.

## UX / DX / AX

**User (UX).** Invisible, correctly. The only user-facing change is that
`CONTRACT.md` gains a stability banner, which matters to exactly one kind of
user: the one deciding whether to build on this.

**Developer (DX).** The deliverable is: *clone, run one command, learn your
level*. If that takes more than five minutes, the release failed regardless of
how correct the suite is.

`RUNNER.md` must be short enough to read in one sitting. Two pages. If it needs
more, the contract is too complicated to have earned a freeze.

**Agent (AX).** An agent asked to port this to another language should be able to
work from `CONTRACT.md` + `conformance/` alone, without reading our TypeScript —
and then check itself. That is the real test of whether the contract is a
specification or a description of our implementation. Worth actually trying
before declaring the release done.

## Tests

- [ ] our implementation passes L1 through L4
- [ ] the suite catches a deliberately broken implementation at each level
      (mutation testing: disable a check, the suite must fail)
- [ ] expected results reference only codes, never message text
- [ ] every fixture has a comment saying which bug it commemorates
- [ ] `RUNNER.md` is complete enough that a second implementation built from it
      alone passes L1 — verified by actually doing it, in any language

## Docs

- `conformance/RUNNER.md` — new
- `CONTRACT.md` — stability statement, freeze policy, pointer to the suite
- `CONCEPT.md` — stability statement
- `README.md` — conformance badge and the one-command claim
- `docs/PORTING.md` — porting now means "pass the suite", which is a much
  shorter document than what is there today
- `CHANGELOG.md` — the freeze, stated once and unambiguously

## Risks

**Freezing too early.** A field that turns out to be needed after the freeze
becomes an extension field forever, which is survivable but ugly. Mitigation:
four releases of pressure first, and the freeze is on *core* — standard fields
can still be added with an argument.

**The suite encodes our quirks.** Fixtures written against our parser can
accidentally require behaviour the contract does not specify. Mitigation: every
expected result must trace to a numbered rule in `CONTRACT.md` §1. If it cannot,
either the rule is missing or the fixture is testing an implementation detail.
This check is mechanical and should be a test.

**Nobody ports it.** Then the freeze cost nothing and the suite is still a good
regression harness for us. Acceptable downside.

## Done when

- [ ] `npm run conformance` passes L1–L4 and runs in CI
- [ ] mutation testing proves the suite has teeth
- [ ] every expected result cites a contract rule
- [ ] a second implementation, written from `RUNNER.md` alone, reaches L1
- [ ] `CONTRACT.md` and `CONCEPT.md` carry stability statements

## Kill criteria

- If 1.1.0 has needed a breaking change during 0.3–0.6, do not freeze. Ship
  0.7.0, absorb the change, and revisit. A freeze announced and then broken is
  worse than one deferred.
- If `RUNNER.md` cannot be written in two pages, the contract is too complex to
  claim portability. Simplify the contract or drop the claim — do not ship a
  forty-page runner and pretend.
